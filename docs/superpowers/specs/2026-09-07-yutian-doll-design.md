# 雨田娃娃双人换装网站设计规格

日期：2026-09-07

## 1. 项目目标

构建一个手机优先的二维换装网站，供两个人通过同一条专属链接共同装扮同一个娃娃。两个人无需注册或输入密码，打开链接即可进入唯一且永久保存的房间，并实时看到对方的换装操作。

网站通过 GitHub Pages 发布，代码与美术素材存放在公开 GitHub 仓库 `hubuxi19-commits/YuTian-Doll`。Cloudflare 仅用于实时连接与装扮状态存储，不存储图片。

## 2. 产品范围

### 2.1 首版包含

- 固定不变的娃娃身体、脸、五官和现有发型。
- 二维透明 SVG 或 PNG 服装和配饰图层。
- 套装、上衣、下装、鞋子、发饰、眼镜、包包和手持物分类。
- 点击服装后自动对齐并替换同类别服装。
- 发饰、眼镜、包包和手持物支持移动、旋转和缩放。
- 两个人对同一个娃娃进行实时同步操作。
- 对方在线状态和简短操作提示。
- 当前装扮永久保存，重新打开链接后恢复。
- 1280×1280 高清 PNG 导出。
- 只读成品分享链接。
- 约 15 件首批示例素材，覆盖日常、约会和公主风，兼有整套服装与可混搭单品。

### 2.2 首版不包含

- 账号、登录、密码或公开房间大厅。
- 文字聊天、语音聊天或表情互动。
- 商城、付费、积分或物品解锁机制。
- 3D 模型、骨骼动画、眨眼或呼吸动画。
- 用户上传素材或网页内制作新素材。
- 复杂版本历史、多人权限和管理后台。

## 3. 用户体验

### 3.1 进入网站

用户通过包含随机房间标识的专属 GitHub Pages 链接进入。浏览器保存该标识，后续打开主网址时可自动返回同一房间。没有房间标识时，网站生成唯一房间并更新地址。

### 3.2 页面布局

- 顶部栏显示网站名称、连接状态、对方在线状态和导出按钮。
- 中央为正方形娃娃画布，在手机屏幕上优先占用可用宽度。
- 底部为可左右滑动的分类栏和物品缩略图抽屉。
- 桌面端保持同样的信息结构，将物品栏扩展到画布侧边。
- 视觉采用奶油白、淡粉和柔和棕色，使用圆角卡片、细描边和轻手账质感。

### 3.3 换装操作

- 选择服装时，物品按照预设锚点、尺寸和图层顺序自动显示。
- 同类别默认只允许一个物品；选择新物品会替换旧物品。
- 套装会占用其声明的服装槽位，例如上衣、下装和鞋子，避免图层冲突。
- 可调整配饰被选中后显示轻量变换控件；手机支持单指拖动和双指缩放、旋转，电脑支持拖动和控制柄。
- 新物品使用短暂淡入和轻微弹出效果，娃娃原稿本身不发生动画或形变。
- 用户可以移除当前分类物品，并可一键恢复默认空白穿搭。

### 3.4 双人体验

- 本地操作立即显示，再异步发送到服务器。
- 对方的操作在收到后立即应用，并显示简短提示，例如“对方更换了上衣”。
- 同一物品发生并发修改时，以服务器最后接受的有效操作为准。
- 页面显示在线人数；在正常使用场景中将另一位在线用户显示为“对方在线”。
- 不展示远端光标，避免遮挡娃娃和增加不必要的同步流量。

### 3.5 保存、导出与分享

- 每次有效操作都会更新房间快照，房间没有自动过期时间。
- 导出时按原始 1280×1280 坐标系重新渲染所有图层，生成 PNG 文件。
- 导出内容不包含界面、选中框、在线状态或操作提示。
- “分享成品”创建一个只读快照标识。打开快照链接只能查看和下载，不能改变原房间状态。

## 4. 美术资源规范

### 4.1 基础稿

- 使用现有 1280×1280 娃娃稿作为不可变底图。
- 不重绘、裁剪或修改身体、面部、五官及现有发型。
- 网页显示时只进行等比例缩放；导出时恢复到 1280×1280。

### 4.2 换装素材

- 固定服装优先使用透明背景 SVG，并统一采用 1280×1280 视图坐标，以保证自动对齐；后续也允许使用同尺寸透明 PNG。
- 服装只绘制覆盖区域，其余位置保持透明。
- 可移动配饰可以采用紧边透明 PNG，但必须在清单中声明默认锚点和尺寸。
- 美术清单记录物品编号、名称、分类、风格、占用槽位、默认变换、图层级别、缩略图和资源路径。

### 4.3 首批素材清单

首批固定为 15 件素材，覆盖日常、约会和公主风：日常背带裙套装、约会蕾丝连衣裙、公主蓬蓬裙、奶油针织开衫、粉色连帽卫衣、蝴蝶结衬衫、格纹百褶裙、柔粉 A 字裙、白色运动鞋、玛丽珍鞋、蝴蝶结发卡、圆框眼镜、迷你斜挎包、珍珠小皇冠和手持花束。制作阶段可以微调颜色与纹样以匹配原稿，但不得替换类别或扩大数量。

## 5. 技术架构

### 5.1 前端

- React、TypeScript 和 Vite 构建静态单页应用。
- Konva 与 React-Konva 负责二维图层渲染、命中检测、触摸变换和高清导出。
- 应用状态分为房间快照、连接状态、素材清单和仅本机存在的界面状态。
- GitHub Actions 在 `main` 分支更新后执行检查、构建并部署 GitHub Pages。

### 5.2 实时服务

- 一个 Cloudflare Worker 提供健康检查、房间 WebSocket 和只读快照接口。
- 唯一房间映射到一个 SQLite 后端的 Durable Object。
- Durable Object 作为该房间的顺序协调点，验证操作、增加版本号、持久化快照并广播更新。
- 使用 WebSocket Hibernation API，让连接空闲时可以休眠而不主动断开。
- 图片和缩略图不经过 Cloudflare，始终由 GitHub Pages 提供。

### 5.3 房间状态

房间快照至少包含：

- `roomId`：不可猜测的随机标识。
- `version`：服务器递增版本号。
- `equipped`：各服装槽位当前使用的物品编号。
- `accessories`：可移动配饰的物品编号和位置、比例、角度。
- `updatedAt`：服务器更新时间。

所有坐标使用 1280×1280 逻辑画布坐标，避免不同屏幕尺寸之间出现位置漂移。

### 5.4 消息模型

- `join`：客户端加入并请求完整快照。
- `presence`：在线人数变化。
- `equip`：更换或移除服装槽位。
- `remove`：移除指定服装槽位或配饰。
- `transform`：更新配饰位置、角度和比例。
- `reset`：恢复默认空白穿搭。
- `snapshot`：服务器返回完整权威状态。
- `ack`：服务器确认操作及最新版本。
- `error`：服务器拒绝无效消息。

拖动和双指操作在本机逐帧显示，但网络更新会限频；交互结束时必须发送最终变换值。

## 6. 安全与隐私

- 网站和素材均为公开内容，不将专属链接视为强身份认证。
- 房间标识使用 UUID v4，保留完整的 122 位随机空间，降低被偶然猜中的可能性。
- Worker 仅允许预期的 GitHub Pages 来源，并为本地开发保留明确的开发来源配置。
- 服务端只接受已知消息类型和已存在的物品编号。
- 坐标、比例、角度、字符串长度、消息体大小和发送频率均设置上限。
- 仓库中不得保存 Cloudflare API Token、账户密钥或其他部署凭证。

## 7. 异常处理

- 初次连接失败时，加载本机最后一次快照并进入离线模式。
- 离线操作写入本机待发送队列；重连后先获取服务器快照，再按顺序提交仍然有效的操作。
- 如果服务器版本已更新，同类别冲突遵循服务器接收顺序，客户端随后采用服务器权威快照。
- 图片加载失败时显示对应物品的占位提示，但不阻塞其他物品或导出流程。
- 导出失败时保留当前装扮并给出重试提示。
- WebSocket 使用带退避的自动重连，不进行高频无限重试。

## 8. 测试与验收

### 8.1 自动测试

- 素材清单完整性、编号唯一性和资源路径检查。
- 服装槽位替换及套装占位规则。
- 图层排序和配饰变换边界。
- 服务端消息校验、版本递增和最后写入生效规则。
- 断线、重连、离线队列和永久快照恢复。
- 只读快照不可修改原房间。
- PNG 导出尺寸为 1280×1280，且不包含界面元素。

### 8.2 人工验收

- 在两个独立浏览器窗口进入同一链接，验证换装、配饰变换和在线状态实时同步。
- 刷新或关闭后重新进入，确认装扮仍然存在。
- 模拟断网后操作并恢复网络，确认最终状态收敛一致。
- 在常见手机尺寸验证分类滑动、点击、拖动、双指缩放和旋转。
- 在桌面端验证画布适配、鼠标变换和 PNG 下载。
- 验证 GitHub Pages 地址可直接访问，Cloudflare 免费部署不包含任何仓库密钥。

## 9. 部署与用户需要完成的事项

实施完成后，用户需要：

1. 在 Cloudflare 登录自己的账户并创建或授权 Workers 项目部署。
2. 将部署得到的 Worker 地址配置到 GitHub 仓库变量。
3. 在 GitHub 仓库设置中启用 GitHub Pages 的 GitHub Actions 发布来源。

项目将提供逐步操作说明和可复制的配置值。除 Cloudflare 与 GitHub 的账户授权外，构建、测试和部署配置均随仓库提供。

## 10. 完成标准

当以下条件全部满足时，首版视为完成：

- 两个人能通过同一专属链接进入唯一房间且无需登录。
- 服装自动对齐，配饰可以在手机和电脑上调整。
- 双方操作实时同步，刷新后状态永久恢复。
- 原始娃娃稿在显示与导出中保持不变。
- 可下载 1280×1280 PNG，并可生成只读成品链接。
- 首批约 15 件三种风格素材可正常使用。
- 自动测试通过，GitHub Pages 构建流程可用，Cloudflare 部署说明完整。
